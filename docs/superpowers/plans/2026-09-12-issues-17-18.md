# Issues 17 and 18 implementation plan

**Goal:** Bound complete Claude HTTP responses and prevent structured credential fields from surviving crash-log redaction.

**Scope:** Existing .NET 8 clients and local crash logging only. Keep endpoints, polling policy, credential persistence, and crash-only logging behavior. No additional dependencies.

**Requirements:** [Issue 17](https://github.com/kmch4n/UsageBeacon/issues/17) and [Issue 18](https://github.com/kmch4n/UsageBeacon/issues/18).

## 1. Complete-response limits

- [x] Add synthetic HTTP-content tests for both clients: stalled bodies, known and unknown oversized lengths, exact size boundary, caller cancellation, and recovery on the following request.
- [x] Run the tests against the original clients and record the expected failures.
- [x] Use `HttpCompletionOption.ResponseContentRead` in `AnthropicUsageApiClient` and `ClaudeOAuthClient`. This makes the existing HttpClient deadline and 64 KiB buffer limit apply to the complete response. Keep the existing cancellation/timeout/network error mapping.
- [x] Verify that a timed-out request releases the view-model refresh gate and a subsequent refresh publishes usage.

The complete response is buffered before status classification, including error responses. A stalled or oversized error body therefore becomes a bounded transport failure rather than a status-specific error. Normal 401/429 responses must retain their existing mapping and Retry-After handling. Redirects remain disabled; neither client logs request or response bodies.

## 2. Structured crash redaction

- [x] Add failing synthetic tests for quoted credential keys and values, whitespace and escaped characters, and complete exception records with inner exceptions.
- [x] Extend credential-field redaction before existing standalone token patterns; redact an entire quoted value rather than only its first whitespace-delimited token.
- [x] Preserve timeout-based omission of original crash details and existing profile, account, bearer, JWT, and API-key behavior.
- [x] Revise README and bug-report attachment guidance to describe best-effort redaction and require review before sharing.

## 3. Verification and handoff

- [x] Run focused tests, then the complete xUnit suite and Debug/Release builds.
- [ ] Review the security-sensitive diff independently; report any review findings before applying additional changes.
- [x] Update the changelog and repository decision/status records with verified behavior and limits.
- [ ] Remove temporary build output while preserving `publish/latest`.

No commit, push, release, or Issue state change is part of this implementation task. Tests must use synthetic credentials and temporary fixtures only.
