# UsageBeacon v1.2.0 Release Preparation

## Goal

Ship the current dashboard and reliability improvements as a reviewable v1.2.0 release, with accurate screenshots and release notes that describe changes since v1.1.0.

## Approach

1. Compare the v1.1.0 tag, current working tree, previous release notes, and release workflow. Verify the GitHub identity and preserve existing changes.
2. Capture the actual WPF dashboard using illustrative usage data in a separate screenshot harness. Review images for readability and absence of personal usage or credentials before updating README.
3. Update README dashboard copy and screenshots, v1.2.0 changelog, project version, and a dedicated release note file. Wire the tag workflow to use the file, retaining generated notes as a fallback.
4. Run Debug and Release tests, a self-contained publish, release checklist checks, and image inspection. Confirm the tagged-source workflow will package the intended version and checksum.
   Apply the selected theme to the dashboard scrollbar and recapture both images after the independent visual review.
5. Publish only after the local result and release text are concrete and reviewable.

## Constraints

- Keep public-facing repository text in English and files in UTF-8.
- Do not include personal usage history or credentials in screenshots.
- Keep the WPF application and data collection behavior unchanged for screenshot generation.
- Do not mix upstream release history with this fork's v1.1.0-to-v1.2.0 change list.
